# 2 产品概述

## 2.1 定位

个人用的工时与工资自查工具。用户自己填每天的工时，App 按项目薪资配置算出日工资、月工资，再给报表和导出。数据默认存本地，登录后云同步。

## 2.2 用户与场景

- 计时或排班制员工：每天按班次记正班、加班、周末、节假工时。
- 要核对工资条的人：月底拿报表逐日对，差在哪天一眼看到。
- 同时干几个项目的人：不同项目不同薪资规则，切换项目分别记录。

## 2.3 不做的事

- 不判断加班是否合法，不做合规审查。
- 不代发工资，不与用工单位的考勤系统对接。
- 不承诺算出的金额等于实际到手。社保、个税只作为可配置的扣款项。

## 2.4 形态

uni-app 混合应用，iOS 与 Android 双端。iOS 8.0.9 b19 是自用改版：在原版上加了自定义考勤周期，底栏改成悬浮式。底栏改动属于界面层，不影响本文任何计算规则。

## 3.3 全局规则

- 不登录也能记完所有数据，记录存本地；登录后自动上传，账号只能单设备登录 [确认]。
- 任何设置类页面改完返回，记录页立刻刷新（页面间用 jilu_init 事件）[确认]。
- 金额一律保留两位小数；整数不带小数点后两位 [确认，RecordProject 显示逻辑]。
- 有空态和错误态：无记录显示“未记录工时数据”，无补贴显示“暂无日补贴项目”，网络失败给中文提示，不静默失败。

# 5 计算规则规格

以下规则中，[确认] 来自明文函数，[推断] 由数据结构与调用链反推。做验收时以真实数据反算为准。

## 5.1 单日工时

```
a = (结束小时 × 60 + 结束分钟) - (开始小时 × 60 + 开始分钟)
if a < 0: a = a + 1440        # 跨午夜补一天
h = a / 60
返回：整数原样返回，否则保留两位小数
```

一天多段逐段累加。记录方式为时长记录时直接用手填小时数，手填值优先于时间段换算。[确认：getTimeDuration]

## 5.2 时薪口径

```
月时薪 = 底薪 ÷ 该年该月的计薪工时（monthConfig[年].hours[月-1]）
固定时薪 = 底薪 ÷ 21.75 ÷ 8
```

实测：3300 ÷ 176 = 18.75；3300 ÷ 144 = 22.917，两次都吻合。[确认]

## 5.3 各类型时薪

| 类型 | 取哪个值 | 备注 |
|---|---|---|
| 正班 zb | 配置里的正班时薪 | 不取整 |
| 加班 jb | 综合工时制取加班时薪原值，其它方式取整 | 依项目计薪方式分支 [推断] |
| 周末 zm | 周末时薪，取整 | [推断] |
| 节假 jj | 节假时薪，取整 | [推断] |

## 5.4 当天工时费

```
if 金额被手动改成 0: 返回 0
if 项目计薪方式与记录类型匹配: 返回 取整(时长 × 该类型时薪)
else: 返回 0
```

含义：模式不匹配的类型只记时长，不计钱。例如“底薪加加班”模式下只算加班费，正班时长不计费。[推断]

## 5.5 休假与缺勤

```
if 扣款类型 = 正班时薪 且 时长 > 0: 扣 = 取整(时长 × 时薪 × 倍数)
elif 类型 = 其它: 扣 = 固定金额
结果按类型带正负号：补贴为正，扣款为负
```

## 5.6 补扣

按时薪计价：金额 = 时长 × 时薪 × 倍数；按金额计价：直接取填写的数；按次数计价：单价 × 次数。倍数可选 0.2、0.5、1、1.5、2、3。

## 5.7 月度汇总

- 月份键：年-月；年度记录键按年分文件。
- 区间枚举按考勤周期起止逐日展开，跨月跨年都连续。
- 金额运算走 plusNum、minusNum、timesNum 三个函数，先处理浮点误差再相加，不做裸加减乘除。
- 汇总口径：底薪、四类工时与金额、补贴合计、扣款合计、日结合计分别累加，最后合成实发。

## 5.8 四种计薪方式的算例

设定：底薪 3300，每月正班 176 小时，正班时薪 18.75，平日加班倍率 1.5。

| 方式 | 计价口径 | 某日 8 小时正班 + 2 小时平日加班 | 说明 |
|---|---|---|---|
| 正班加加班 | 正班按正班时薪，加班按加班时薪 | 150 + 56.25，取整后约 206 | 两类都计费 |
| 底薪加加班 | 正班时长只记不算钱，月底给底薪；加班单独算 | 56.25，月底再加 3300 | 适合固定月薪、只关心加班费的人 |
| 综合工时制 | 月正班时长满 176 小时即为底薪，超出部分算加班 | 当月满 176 小时后，超出的每小时按加班时薪 | 适合综合工时岗位 |
| 小时计算 | 一个固定时薪，平日与周末不加倍，节假单独设 | 8 × 时薪，加班同样乘固定时薪 | 适合临时工、按小时结算 |

假定当月正班 184 小时走综合工时制：前 176 小时对应底薪 3300，超出 8 小时按加班时薪 28.125 计，合计 3525。[推断，需真实数据核]

休假算例：事假 8 小时，扣时薪 1 倍，记 -150；若为薪假按 1 倍计薪，记 +150。

## 5.9 精度与取整

- 时长统一两位小数，金额显示两位小数。
- 金额内部按分处理，避免 0.1 + 0.2 类的浮点误差。
- 取整发生在单类型金额汇总时，先取整再相加，不是先加再取整。[推断]

# 7 非功能需求

## 7.1 离线可用

全部记录与设置在本地完成，不联网也能记、能算、能看报表。联网只用于云同步、VIP、工资条照片、导出 Excel。

## 7.2 同步

登录后自动同步，间隔由客户端控制；手动同步入口在账号页。同步冲突以服务端时间为准，本地未同步的改动不静默丢弃，失败要给出可见提示。[部分推断]

## 7.3 性能

以下为验收目标值，不是实测结果：

- 冷启动到记录页可操作不超过 3 秒（中端机）。
- 切换月份、统计重算在 1 秒内返回，超过要显示加载态。
- 单年记录量按每天 1 条、最多 5 段估算，读写不卡顿。

## 7.4 兼容

- iOS 与 Android 双端；iOS 8.0.9 b19 自用版底栏为悬浮式，交互与原生 Tab 一致。
- 日历含农历与节气，跨年、闰月显示正确。
- 系统深色模式下文字对比度满足可读。

## 7.5 隐私与权限

| 权限或数据 | 用途 | 拒绝后的行为 |
|---|---|---|
| 通知 | 每晚记录提醒 | 只少提醒，不影响记录 |
| 相册与相机 | 工资条照片、报表图片 | 不能加照片，其它功能正常 |
| 账号信息（头像、昵称、邮箱、第三方账号） | 登录与展示 | 不登录可离线使用，不能同步 |
| 剪贴板 | 复制报表文本 | 复制失败给提示 |

个人信息收集清单在关于页可查，逐项写明用途与采集状态。

## 7.6 安全

- 本地数据明文存储，设备丢失即等于数据泄露，敏感场景自行加设备锁。
- 退出登录清除本地数据；注销账号需输入确认文字，且不可恢复。
- 账号单设备在线，降低共享账号导致的数据覆盖。

## 7.7 可用性

- 空态文案明确：未记录、暂无补贴、暂无数据三类各自不同。
- 错误提示用中文短句，说清下一步（例如“请先登录后再操作报表”）。
- 破坏性操作（删除记录、批量删除、退出、注销）都要二次确认。
- 报表可隐藏金额，便于截图外发。

## 7.8 可维护性

b19 的三处改动都以补丁形式存在：页面注入脚本、周期引擎、加密层调用加参数。补丁必须保持可整段撤掉即回原版，撤掉后功能与 8.0.9 原版一致。改动不得触碰 5.1 至 5.7 的计算函数签名。
